En el contexto de una Screaming Architecture, la carpeta lib/ (abreviatura de library) es el lugar donde viven las configuraciones e instancias de librerías de terceros.Mientras que en features/ tienes el "qué" hace tu app (tu negocio), en lib/ tienes el "cómo" te conectas con las herramientas externas. 
No es para lógica de negocio, sino para infraestructura.
Aquí tienes el desglose de qué poner allí para mantener la eficiencia y el orden:
  1. Clientes de API e Instancias (SDKs)Si usas Axios, Fetch con esteroides, Firebase, Supabase o Prisma, sus configuraciones iniciales van aquí.Ejemplo: lib/api-client.ts (donde configuras la URL base, interceptores de tokens y headers de Axios).Ejemplo: lib/supabase.ts (donde inicializas el cliente con las variables de entorno).
  2. Configuraciones de Herramientas de EstiloSi usas herramientas que requieren un "setup" programático.Ejemplo: lib/panda-css.ts o configuraciones específicas de temas complejos que no sean puramente CSS.
  3. Adaptadores de Librerías ExternasSi usas una librería de fechas (como date-fns o dayjs) o de gráficos (como echarts), y quieres crear una instancia configurada con el idioma local, plugins o formatos por defecto.Ejemplo: Un archivo lib/date.ts que ya exporta dayjs con los plugins de "relativeTime" y el idioma español ya cargados.4. Definiciones de Constantes de InfraestructuraCosas que no cambian y definen cómo opera la tecnología, no el negocio.Ejemplo: lib/constants.ts para manejar versiones de la API o tiempos de timeout.
  
  Diferencia clave: lib/ vs utils/Es muy común confundirlos, pero para escalar bien, sepáralos así:Característicalib/ (Infraestructura)utils/ (Lógica pura)ContenidoInstancias de SDKs, configuraciones de Axios, Funciones matemáticas, formateo de strings, validaciones simples.
  Dependencias: Suele importar librerías de node_modules.
  Normalmente no tiene dependencias externas (es JS/TS puro). 
  Estado:Puede mantener un "estado" (ej. la sesión de Firebase).Son funciones puras (misma entrada = misma salida).EjemploaxiosInstance.get('/...')formatCurrency(1000)

- Ejemplos que van aca
export const apiClient = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_URL,
  timeout: 10000,
});

// Interceptor para inyectar el token (Lógica de infraestructura)
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
Regla de oro: Si mañana decides cambiar Axios por fetch, o Firebase por Supabase, el 90% de los cambios deberían ocurrir dentro de la carpeta lib/, sin que tus features/ tengan que enterarse de los detalles técnicos de la implementación.
